# CraftSpirits — автоматика дистилляции и ректификации

Самодельная замена БКУ-07М на базе ESP32 (firmware) + Raspberry Pi 4 (standalone Python-сервис с веб-UI и touchscreen на щите). Цель — повторить функционал заводской автоматики, убрать её ограничения и оставить место для собственных алгоритмов. Без зависимости от Home Assistant — можно ставить «как готовое устройство».

## 1. Целевые режимы (MVP → V1)

| Режим | MVP | V1 |
|---|---|---|
| Дистилляция (потстил), отсечка по T куба | ✅ | + отсечка по ΔT/dt и по объёму |
| Ректификация старт-стоп с клапаном | ✅ | + автокалибровка пауз стабилизации |
| ШИМ-отбор (пропорциональный) | — | ✅ |
| Управление дефлегматором (PID по T пара) | — | ✅ |
| Барокоррекция T кипения по BME280 | — | ✅ |
| Аварийная отсечка (soft+hard) | ✅ | ✅ |
| Логирование + графики в HA | ✅ | + экспорт CSV рецепта |

## 2. Архитектура

**Standalone-приложение, без зависимости от Home Assistant.** Brain в виде Python-сервиса на Raspberry Pi 4, ESP32 — «глупая» периферия с safety, локальный 7" touchscreen на щите + доступ с телефона по LAN.

```
   ┌── DS18B20 × 4–6 (1-Wire)
   │
[ESP32-S3]──ESPHome──── Wi-Fi / native API ───┐
   │                                           │
   ├── SSR ТЭНа (slow PWM)                     │
   ├── SSR клапан отбора                       │
   ├── SSR клапан воды                         │
   ├── Реле enable-контактора                  │
   └── E-stop / биметалл / термопред (GPIO in) │
                                               │
                       ┌───────────────────────┴───────────────┐
                       │  Raspberry Pi 4 (4 GB) + USB-SSD       │
                       │                                        │
                       │  CraftSpirits Controller (Python)      │
                       │  ├── FastAPI + WebSocket               │
                       │  ├── aioesphomeapi → ESP32             │
                       │  ├── state machines (PotStill,         │
                       │  │       RefluxStartStop, ...)         │
                       │  ├── SQLite (сессии, рецепты, события) │
                       │  └── Telegram alerts (опц.)            │
                       │                                        │
                       │  Web UI (Svelte + Chart.js)            │
                       │  http://still.local:8000               │
                       │       ▲                                │
                       │       │                                │
                       │  Chromium kiosk → localhost:8000       │
                       │       │                                │
                       └───────┼────────────────────────────────┘
                               │ HDMI + touch
                       ┌───────┴──────────┐
                       │ 7" Touch Display │  ← на дверце щита
                       └──────────────────┘
```

**Разделение ответственности — критично для безопасности:**

- **ESP32 (ESPHome)** — единственный, кто физически управляет SSR/реле. Знает только примитивы: «выставь мощность ТЭНа N%», «открой клапан». Имеет независимые safety-инварианты, которые отрубают железо при их нарушении даже без команды сверху.
- **Raspberry Pi 4 (CraftSpirits Controller)** — высокоуровневая логика режимов, рецепты, история, UI. Падение Pi не должно приводить к небезопасному состоянию: ESP должен сам уйти в safe state по watchdog (нет команды > 30 сек).
- **Touchscreen** — это просто браузер, открытый на `localhost:8000`. Падение Chromium не влияет на ничего, кроме UI.

**Почему не Home Assistant**: standalone делает систему независимой от HA-обновлений, упрощает развёртывание (один Docker образ или systemd-юнит), позволяет упаковать как готовый продукт. Минус — теряем «бесплатные» интеграции HA (но Telegram и базовый веб-доступ делаем сами).

**Почему именно ESPHome на ESP32** (а не своя прошивка): YAML-конфиг вместо C++, OTA из коробки, отлаженные драйверы DS18B20/BME280/slow-PWM, официальный Python-клиент `aioesphomeapi` для разговора с Pi.

## 3. BOM (Bill of Materials)

> **Зафиксированы решения:** ESP32-S3-DevKitC-1, ТЭН 3–5 кВт, охлаждение дефлегматора — водопроводная вода через соленоидный клапан 230В (без помпы). **Сборка без пайки** — все модули заказываем готовыми, соединения через винтовые клеммы, Wago 221 и обжимные гильзы НШВИ.

### Стратегия «без пайки»

Заменяем пайку на три механизма:
- **Винтовые клеммы** на каждом модуле (выбираем модули с встроенными)
- **Wago 221** — рычажные клеммники для 230В соединений и распределения шин датчиков
- **НШВИ + кримпер** — оконцовка многожильного провода в винтовые клеммы (5 сек на провод)
- **DuPont F-F джамперы** — сигнальные соединения между модулями и ESP

Единственный возможный риск: если попадётся BME280 без впаянных штырей. В BOM явно указано «assembled» — проверяйте перед заказом.

| Силовой контактор | модульный AC 230В, 25А, NO | 1 | Включается реле «enable» с ESP, разрывается термопредохранителем. Без него ТЭН не запитан в принципе. |

**Принцип hardware safety:** ТЭН питается через цепочку `автомат → УЗО → E-stop (NC) → биметалл куба (NC) → термопредохранитель (NC) → катушка контактора → SSR → ТЭН`. Любой разрыв в цепи NC = ТЭН обесточен, и софт тут не участвует.

Всё для самостоятельной сборки силового узла + цифры для проверки. Под однофазную сеть 230 В AC, ТЭН резистивный, нагрузка до 5 кВт.

### 5.1 Полная топология

```
[Дом, главный щит]
     │
   УЗО 30 мА AC, ≥25 А
     │
   Автомат C25 (под 5 кВт) или C16 (под ≤3 кВт)
     │
     │  ВВГнг 3×4 (или 3×2.5)
     ▼
┌─────────────────── НАШ ЩИТ (DIN, IP54) ──────────────────────────┐
│                                                                   │
│   L ───┬─────────────────────────────────────────────────         │
│        │                                                          │
│        ├──► Mean Well IRM-15-5 (230AC → 5V DC, для ESP+реле)      │
│        │                                                          │
│        ├──► БП Raspberry Pi 4 (отдельный 5V 3A USB-C PSU)         │
│        │                                                          │
│        │   ┌──── SAFETY CHAIN ──── катушка контактора ────┐       │
│        │   │                                              │       │
│        ├───┤ E-stop NC → KSD9700 NC → KSD9700 NC →       │       │
│        │   │ термопред NC → ESP-enable relay NO →        │       │
│        │   │ катушка KM (~5W, 230VAC)                    │──┐    │
│        │   └──────────────────────────────────────────────┘  │    │
│        │                                                     │    │
│   N ───┤                                                     │    │
│        │                                                     │    │
│   ╔════╪═════════════════════════════════════════════════════╪══╗ │
│   ║  СИЛОВОЙ КОНТАКТОР KM (2NO 25A, катушка 230VAC) ─ замок ║ │
│   ║                                                          ║ │
│   ║  L1 (после KM) ──► предохр 25A ─► SSR Fotek-80DA ─► ТЭН ║ │
│   ║                                          │              ║ │
│   ║                                          └─ R-C снаббер ║ │
│   ║                                                          ║ │
│   ║  L2 (после KM) ──► Omron G3MB ─► соленоид воды 230V     ║ │
│   ╚══════════════════════════════════════════════════════════╝ │
│                                                                   │
│   L (до KM, всегда живая) ──► Omron G3MB ─► клапан БКУ           │
│           (отбор не зависит от контактора — но E-stop его         │
│            всё равно снимет через ESP по watchdog)                │
│                                                                   │
│   PE ──┬─► корпус щита                                            │
│        ├─► корпус ТЭНа                                            │
│        └─► корпус БКУ / дефлегматора                              │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

**Ключевая идея**: силовой контактор — это «общий замок». Когда он отжат, ТЭН и клапан воды физически обесточены, даже если SSR залип в проводящем состоянии. Контактор отжимается:
- Любым размкнутым NC-контактом в safety chain (E-stop, биметалл, термопред)
- Размыканием ESP-enable relay (программная команда от Pi или watchdog ESP)
- Пропаданием 230В в сети (катушка обесточена)

### 5.2 Safety chain — детально

Серийная цепь из NC-контактов аварийников + NO-контакт ESP-enable relay, замыкающая катушку силового контактора:

```
       Линия L (230VAC)
              │
        ┌─────┴─────┐
        │  E-stop   │  ◄── грибок 22мм, NC, фиксируемый
        │   NC      │     (нажат → разрыв)
        └─────┬─────┘
              │
        ┌─────┴──────┐
        │ Биметалл#1 │  ◄── KSD9700 110°C, NC,
        │  на кубе   │     на корпусе куба через термопасту
        │   NC       │     (T > 110°C → разрыв)
        └─────┬──────┘
              │
        ┌─────┴──────┐
        │ Биметалл#2 │  ◄── второй на корпусе SSR-радиатора
        │ на радиат. │     (если перегрев SSR > 110°C → разрыв)
        │   NC       │
        └─────┬──────┘
              │
        ┌─────┴──────┐
        │ Термопред  │  ◄── керамический, 130–140°C, NC, одноразовый
        │   NC       │     рядом с биметаллом #1, «последний рубеж»
        └─────┬──────┘
              │
        ┌─────┴─────┐
        │  ESP-     │  ◄── релейный модуль 1ch, катушка от GPIO 12
        │  enable   │     NO-контакт: замыкается когда ESP активирует
        │  relay NO │     (нет питания / ESP в reset → разомкнут → KM отпал)
        └─────┬─────┘
              │
        ┌─────┴─────┐
        │ Катушка   │  ◄── ABB ESB25-40N-06 / Schneider iCT25 / IEK
        │ контакт.  │     230VAC, ~5W, втягивание ~150мА, удержание ~25мА
        │  KM       │
        └─────┬─────┘
              │
       Нейтраль N
```

**Почему именно так:**
- Все аварийники — **NC** (normally closed): «нет питания на катушке = разомкнуто». Любой обрыв провода или поломка датчика = безопасное состояние. (Если сделать NO — обрыв провода имитирует «всё в норме».)
- ESP-enable relay — **NO** (normally open): «нет питания ESP = разомкнуто». При reset/потере питания/прошивке/любом сбое ESP — катушка обесточена, KM отпадает. Программная команда «всё в норме» = удерживать включённым.
- Контакты NC-аварийников должны выдержать ≥0.5 А, 250 В AC. Стандартные грибок и KSD9700 справляются без проблем (катушка KM тянет всего 0.025–0.15 А).

### 5.3 Расчёты для 3 кВт и 5 кВт

#### Токи и сечения проводов

| Цепь | Мощность | Ток (230 В) | Сечение | Допустимо |
|---|---|---|---|---|
| ТЭН 5 кВт | 5000 Вт | **21.7 А** | ВВГнг 3×4 (Cu) | 32 А в трубе, 38 А открыто |
| ТЭН 3 кВт | 3000 Вт | 13.0 А | ВВГнг 3×2.5 (Cu) | 25 А в трубе |
| Соленоид воды | ~10 Вт | 0.04 А | ПВС 2×0.75 | 6 А |
| Клапан БКУ | ~20 Вт | 0.09 А | ПВС 2×0.75 | 6 А |
| Катушка KM | ~5 Вт | 0.022 А | ПВС 2×0.5 | 3 А |
| БП логики 5В (первичная) | ~15 Вт | 0.07 А | ПВС 2×0.5 | 3 А |
| Pi 4 + дисплей (USB-C) | ~15 Вт | 0.07 А | стандартный USB-C | — |

**Везде кратный запас.** Алюминий не использовать ни в каких силовых цепях этого проекта.

#### Падение напряжения на проводке ТЭНа

ВВГнг 3×4 Cu имеет погонное сопротивление **R ≈ 4.61 мОм/м** на одну жилу. При длине трассы 10 м (туда+обратно = 20 м):

```
V_drop = I × 2L × R/L = 21.7 × 20 × 4.61e-3 = 2.0 В = 0.87 % от 230 В
```

Приемлемо. Если трасса >25 м — пересчитайте; на 30 м это уже 2.5–3 %, что снижает мощность ТЭНа на ~5 %.

#### Тепловыделение SSR + размер радиатора

SSR (Fotek SSR-80DA, реальные данные с datasheet): падение напряжения при полной проводимости **V_on ≈ 1.5 В** (типично для тиристорной пары).

```
P_diss = V_on × I
3 кВт:  P_diss = 1.5 × 13.0 = 19.5 Вт
5 кВт:  P_diss = 1.5 × 21.7 = 32.5 Вт
```

Допустимая температура корпуса SSR: до 80 °C (выше — резкое снижение допустимого тока, риск отказа). В щите летом окружающая 35–45 °C ⇒ допустимое превышение:

```
ΔT_max = 80 - 45 = 35 °C
R_th_required = ΔT_max / P_diss
```

| Мощность | P_diss | R_th нужно | Что взять |
|---|---|---|---|
| 3 кВт | 19.5 Вт | ≤ 1.79 K/W | Радиатор 120×80×30 мм (≈1.5 K/W) ✅ |
| 5 кВт | 32.5 Вт | ≤ **1.08 K/W** | Радиатор 150×100×40 мм (≈0.9 K/W) ✅ ИЛИ 100×60×30 мм + вентилятор 40×40 12В |

**Важный вывод**: радиатор 100×60×30 мм без вентилятора при 5 кВт перегреется. Варианты:
1. Купить радиатор покрупнее (рекомендуется): «алюминиевый радиатор 150×100×40 для SSR» на AliExpress ~$10
2. Поставить вентилятор: тихий 40 мм 12В с регулировкой по T (через термостат KSD9700 75°C NO)
3. Ограничить мощность до 4 кВт (тогда 100×60×30 справится)

После сборки **обязательно тест в Phase 3** (см. секцию 12, Тест 5): 30 минут полной нагрузки, замер температуры SSR ИК-термометром или контактным.

#### Снаббер RC — когда нужен

| Сценарий | Снаббер? | Почему |
|---|---|---|
| Fotek SSR-80 + ТЭН (резистивная) | **Опционально, рекомендую** | Гасит EMI при коммутации, снижает помехи на 1-Wire и WiFi. R=100 Ω 2 Вт + C=0.1 мкФ X2 250 В AC параллельно ТЭНу, провода как можно короче |
| Omron G3MB + соленоид воды | **Не нужен** | В G3MB-202P встроен MOV и snubber для индуктивных нагрузок |
| Omron G3MB + клапан БКУ | **Не нужен** | Аналогично |
| Реле + катушка контактора | **Желательно** | MOV (варистор) 275 В прямо параллельно катушке контактора — гасит ЭДС самоиндукции при отпускании |

Снаббер для ТЭНа собирается из двух выводных компонентов: плёночный конденсатор 0.1 мкФ X2 + резистор 100 Ом 2 Вт **в последовательной** цепи, всё параллельно ТЭНу. Можно сделать прямо на клеммной колодке через НШВИ. Или купить готовый модуль `RC snubber 0.1uF 100R AC` на AliExpress (~$3).

### 5.4 Контактор — почему модульный и какой

Нужен модульный AC-контактор (на DIN-рейку, тихий — без «щелчков» при включении). Требования:
- **Катушка 230 В AC** (не 24 В DC! Внимательно при заказе)
- **2 NO силовых контакта** (один для ТЭНа, второй для соленоида воды) или 1 NO ≥25 А (соленоид можно через тот же контакт)
- **Ток** ≥25 А для 5 кВт (с запасом), ≥16 А для 3 кВт
- **AC-1 категория** минимум (резистивная нагрузка), AC-3 не нужно

Конкретные модели:
- **ABB ESB25-40N-06** — 25 А, 4NO, катушка 230VAC. Самый «правильный», ~$25
- **Schneider iCT25** — 25 А, 2NO, катушка 230VAC. ~$20
- **IEK КМИ-22510** или **КМ-25** — бюджет, ~$10. Работают, но щёлкают громче

Контактор имеет вспомогательный NO-контакт у некоторых моделей (1NC+1NO) — пригодится для индикации в ESP («контактор реально включился»), но не обязательно.

### 5.5 Заземление PE

Без компромиссов:
- PE-шина в щите → отдельная медная шинка с винтами, не объединять с N
- PE → корпус щита (если металлический)
- PE → **корпус куба** (через болт-«земля» на дне или сбоку)
- PE → корпус БКУ / дефлегматора (если металл)
- PE → корпус Pi 4 (если корпус металлический, например Argon NEO)
- Сечение PE-провода = сечению фазы (4 мм² при 5 кВт)

Проверка после монтажа: мультиметром R < 1 Ом между корпусом ТЭНа и PE-шиной щита. Затем УЗО-тестером (или просто кнопкой TEST на самом УЗО) — должно отрабатывать.

### 5.6 Порядок включения и отключения

Чтобы не «дёргать» SSR:
1. Включение: сначала Pi (boot ~1 мин) → потом ESP подключается к Wi-Fi → отзывается на Pi → Pi даёт команду `enable_contactor` → ESP замыкает enable-relay → KM втягивается → 230 В на SSR → SSR ждёт команду PWM
2. Выключение нормальное: Pi даёт `heater=0, valves=closed, enable=off` → ESP размыкает enable-relay → KM отпускает → пропадает 230 В на ТЭН и клапан воды
3. Аварийное (E-stop, биметалл, термопред, watchdog): KM отпадает мгновенно (≤20 мс = один цикл AC), независимо от состояния SSR. Pi+ESP узнают по входу состояния и записывают событие в БД

## 6. Программный стек

Standalone, два уровня: **ESPHome на ESP32** (firmware) + **CraftSpirits Controller на Pi 4** (Python-сервис с веб-UI).

### 6.1 ESPHome-прошивка (`firmware/esp32-still.yaml`)

Делает только то, что обязано — никакой высокоуровневой логики:

- читает все датчики (DS18B20 + BME280) с периодом 1 с;
- публикует sensor entities через **ESPHome native API** (Pi слушает через `aioesphomeapi`);
- принимает команды: `set_heater_power` (0–100%), `valve_отбора` (on/off), `valve_воды` (on/off), `enable_contactor` (on/off), `beep` (ms);
- ШИМ ТЭНа через **slow PWM** на GPIO → SSR, период 2–5 сек (для термической инерции это правильнее, чем фазовая регулировка);
- **safety automations** (выполняются на самом ESP, **без Pi**):
  - watchdog: если нет валидной команды от Pi > 30 с → heater=0, valve=closed, contactor=off, beep;
  - T куба > `max_kub_temp` (по умолчанию 105°C) → heater=0;
  - T любого критичного датчика == NaN или вне диапазона `(-10, 130)` дольше 5 с → heater=0;
  - E-stop input == low → heater=0, valve=closed, contactor=off;
  - при загрузке: всё в safe state, контактор включается только по явной команде Pi.

## 7. Алгоритмы режимов

### 7.1 Дистилляция (потстил)

```
INIT → HEAT_UP → DISTILLING → SHUTDOWN
```

- `HEAT_UP`: heater=100%, ждём T_kub ≥ `t_start` (по умолч. 80°C).
- `DISTILLING`: heater=`p_work` (60-80%), клапан всегда открыт. Логируем.
- Переход в `SHUTDOWN`: T_kub ≥ `t_stop` (98-99°C, с барокоррекцией) ИЛИ dT_kub/dt > порога (вода пошла).
- `SHUTDOWN`: heater=0, beep, журнал.

### 7.2 Ректификация старт-стоп

```
INIT → HEAT_UP → STABILIZE_TR → HEADS → BODY → TAILS → SHUTDOWN
                                  ↑___pulse___↓
```

- `HEAT_UP`: heater=100%, до T_low_tsarga > 60°C (пар дошёл).
- `STABILIZE_TR`: heater=`p_work_heads`, клапан закрыт, ждём `t_stable` минут с условием |dT_top/dt| < ε (захлёб закончен, флегма пошла).
- `HEADS`: повторяющийся цикл `open(t_open_heads) → close(t_pause_heads)`, длится либо по объёму (если есть счётчик), либо по T_kub ≥ `t_kub_body`.
- `BODY`: цикл `open(t_open_body) → close(wait_until |dT_top/dt|<ε)`. Главное условие выхода: T_top > `t_top_max` (~78.5°C+коррекция) дольше `t_dwell` секунд.
- `TAILS`: открыть полностью либо в другую ёмкость (опц. второй клапан), до T_kub ≥ `t_kub_stop`.
- `SHUTDOWN`: heater=0, valve=closed.

Все пороги — поля в JSON-рецепте в БД, редактируются из UI, версионируются (каждое изменение — новая ревизия рецепта).

### 7.3 ШИМ-отбор

Альтернатива старт-стопу: клапан открывается на `duty * period`, `duty` пересчитывается каждые N секунд по PID от ΔT(top - top_setpoint). Лучше, когда клапан/насос позволяет плавную регулировку.

### 7.4 PID дефлегматора

Если охлаждение дефлегматора управляется (клапан воды или PWM-помпа): PID по T_top → расход. Цель — держать T_top чуть выше setpoint, не давая колонне «закиснуть».

## 8. Безопасность — чек-лист

- [x] Аппаратный термопредохранитель + биметалл-аварийник в силовой цепи (независимо от ESP).

## 12. Dry-тесты — план

Цель — проверить всю логику системы без алкоголя и без реальной дистилляции. Делаем в собранном щите. Лампа вместо ТЭНа, светодиоды/индикаторы вместо клапанов, кружка с водой для прогрева датчиков. **Всё, что описано ниже, выполняется ДО первого боевого запуска.**

### 12.1 Подмены компонентов

| Боевой компонент | Чем заменить для dry test | Зачем |
|---|---|---|
| ТЭН 3–5 кВт | **Лампа накаливания 60–100 Вт** (Е27 в патроне с проводами и вилкой) | Видимая нагрузка, минимум тока (≤0.5 А), не нужен большой радиатор на SSR. Накал ламы видно глазом ⇒ ШИМ проверяется визуально |
| Соленоид воды 230 В | **Лампа-индикатор 230 В неоновая** (зелёная) или сетевой LED 5 В через адаптер | Видимая индикация открытия/закрытия |
| Клапан отбора БКУ | **Лампа-индикатор 230 В неоновая** (красная) | То же |
| DS18B20 (×4–6) | Сами боевые датчики | Опускаем по одному в чашку с горячей/холодной водой, имитируем рост T |
| Куб с ТЭНом | **Электрочайник + датчик внутри** (изолированно, через крышку) | Чайник плавно греет воду — идеальный имитатор ТЭНа для отладки переходов состояний |
| BME280 | Сам боевой | Просто читаем атмосферу комнаты |

Стоимость доп. железа для dry test: ~$10. Лампа в патроне + 2 неонки + чайник, который и так есть.

### 12.2 Последовательность тестов

#### Тест 1 — Базовые I/O (Phase 1)

1. Прошить ESPHome на ESP32, подключить DS18B20 + BME280.
2. Поднять `controller/` на Pi (или ноуте в режиме разработки), подключиться к ESP через aioesphomeapi.
3. В веб-UI на `http://still.local:8000/tests` (экран «Tests») убедиться: все датчики читаются, значения обновляются раз в 1–5 сек.
4. Поднести зажигалку к гильзе DS18B20 (НЕ на пластик!) на 5 сек — T должна вырасти на 10–20 °C, потом упасть.
5. Подышать на BME280 — влажность подскочит на 10–20 %.

**Прохождение**: все 4 датчика T и BME280 видны в UI, реагируют на тепло.

#### Тест 2 — Логические выходы (Phase 2)

1. Собрать щит до уровня «ESP + screw shield + SSR + реле», но **без подключения к 230 В сети**.
2. На вход 230 В подать через лампу-индикатор 60 Вт (т.е. в разрыв линии), чтобы видеть «есть/нет напряжение на нагрузке».
3. Из UI экрана «Tests» нажать `[TEST 5s]` на каждом выходе → соответствующая лампа-индикатор должна загораться на 5 сек.
4. Для ТЭН-выхода: задать ШИМ 50 % на 30 сек → лампа на выходе SSR должна **мигать** с периодом 2–5 сек, ~равные интервалы on/off.
5. Проверить кнопку BEEP → пищит.

**Прохождение**: каждый выход срабатывает по команде, ШИМ виден как чёткое мигание лампы.

#### Тест 3 — Safety chain (Phase 3, до первого боевого)

1. Собрать щит полностью, **но вместо ТЭНа — лампа накаливания 100 Вт в патроне** (через клеммы ТЭНа).
2. Подать 230 В на щит, включить контактор через UI (Tests → ESP→enable → ON).
3. На экране Run задать heater = 100 % → лампа загорается на полную яркость.
4. **Тест E-stop**: нажать грибок → лампа **гаснет МГНОВЕННО** (<1 сек, по сути 1 цикл AC ≈20 мс). Отпустить грибок, заново активировать enable из UI → лампа снова горит.
5. **Тест биметалла**: прогреть KSD9700 феном/зажигалкой до >110 °C → лампа гаснет. Остудить → размкнутый контакт обратно замкнётся, но enable-relay уже отжат safety-логикой ESP, надо включить заново из UI.
6. **Тест термопреда**: **НЕ ТЕСТИРОВАТЬ грубо** — он одноразовый. Просто прозвонить мультиметром в холодном состоянии (должен звонить, R<1 Ом).
7. **Тест watchdog (потеря связи)**: отключить Wi-Fi на роутере или выключить Pi на 60 сек → через ≤30 сек ESP должен сам отжать enable-relay → лампа гаснет, пищалка пищит. Включить обратно, в UI должно показать аварию в логе.

**Прохождение**: каждое размыкание гасит лампу за <1 сек, watchdog срабатывает за ≤30 сек.

#### Тест 4 — Slow PWM ТЭНа под нагрузкой (Phase 3)

1. С лампой 100 Вт вместо ТЭНа задать из UI мощность:
   - 25 % → лампа коротко вспыхивает раз в ~2–3 сек, основную часть периода погашена
   - 50 % → симметричные on/off с равными интервалами
   - 75 % → длинные импульсы on, короткие off
   - 100 % → постоянное свечение
   - 0 % → погасла
2. Замерить мультиметром (True-RMS, если есть) средний ток через лампу при 50 % → должен быть ~½ номинального.

**Прохождение**: ШИМ визуально и метрологически работает.

#### Тест 5 — Тепловой тест SSR (Phase 3, перед боем)

1. Подключить **реальный ТЭН**, налить полный куб **воды** (без браги!).
2. В UI задать мощность 100 %, контактор ON.
3. Каждые 5 минут замерять температуру корпуса SSR ИК-термометром или контактным термопаро-мультиметром.
4. Через 15 минут полной нагрузки **температура SSR должна стабилизироваться ≤ 80 °C** при окружающей 25 °C (т.е. ΔT ≤ 55 °C).
5. Если SSR > 80 °C через 15 минут — **выключить, добавить радиатор крупнее или вентилятор**. Не пытайтесь работать на пределе.

**Прохождение**: T корпуса SSR ≤ 80 °C на полной мощности в течение часа.

#### Тест 6 — Алгоритм потстила «на воде» (Phase 4)

1. Реальный ТЭН, реальные клапаны (вода в дефлегматор течёт реально), куб с **водой** (без браги).
2. В UI запустить режим «Потстил» с параметрами как для дистилляции (T_start=80, T_body=85, T_stop=99).
3. Проверить, что система проходит фазы:
   - HEAT_UP: heater=100 %, ждём пока T_kub дойдёт до 80
   - DISTILLING: heater=p_work, клапан воды открыт (вода поступает), клапан отбора открыт (но сольёт просто горячую воду)
   - SHUTDOWN: при T_kub > 99 → всё гаснет, пищит, сессия закрыта в БД
4. Записать в `docs/calibration.md` фактические времена и поведение для будущей подстройки.

**Прохождение**: все фазы пройдены автоматически, переходы корректные, finалом — safe state.

#### Тест 7 — Симуляция аварий в работе (Phase 4)

С работающим режимом потстила на воде:
1. **Выдернуть провод DS18B20 куба** → через 5 сек (3 чтения подряд с ошибкой) ESP уходит в safe state, в UI авария «Sensor T_kub lost», пищалка. Контактор отжат.
2. **Закоротить провод DS18B20 куба** (фаза → DQ на 1 сек) → 1-Wire CRC error → ESP игнорирует на 5 сек, потом safe state.
3. **Закрыть кран водопроводной воды** в дефлегматор → нет потока, но мы не имеем расходомера ⇒ обнаружим только косвенно: T выхода дефлегматора растёт ненормально. Лог: добавляем мягкую проверку ΔT(out-in) > 50 °C → warning в UI (не авария).
4. **Отключить Pi от сети** → через ≤30 сек ESP watchdog → safe state.

**Прохождение**: все аварии корректно регистрируются и приводят в safe state.
