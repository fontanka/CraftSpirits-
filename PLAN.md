# CraftSpirits — автоматика дистилляции и ректификации

Самодельная замена БКУ-07М на базе ESP32 + Home Assistant. Цель — повторить функционал заводской автоматики, убрать её ограничения и оставить место для собственных алгоритмов.

## 1. Целевые режимы (MVP → V1)

| Режим | MVP | V1 |
|---|---|---|
| Дистилляция (потстил), отсечка по T куба | ✅ | + отсечка по ΔT/dt и по объёму |
| Ректификация старт-стоп с клапаном | ✅ | + автокалибровка пауз стабилизации |
| ШИМ-отбор (пропорциональный) | — | ✅ |
| Управление дефлегматором (PID по T пара) | — | ✅ |
| Барокоррекция T кипения по BME280 | — | ✅ |
| Аварийная отсечка (soft+hard) | ✅ | ✅ |
| Логирование + графики в HA | ✅ | + экспорт CSV рецепта |

## 2. Архитектура

```
[ ТЭН ]──SSR(ZCD)──┐                      ┌── DS18B20 × N (1-Wire)
[Клапан 220В]──Relay──┐                   │
[Помпа охл.]──Relay/PWM──┐                │
                         │                │
                    ┌────┴────────────────┴────┐
                    │         ESP32            │
                    │   (ESPHome + safety)     │
                    └────────────┬─────────────┘
                                 │ Wi-Fi / native API
                    ┌────────────┴─────────────┐
                    │  Home Assistant (RPi)    │
                    │  Lovelace UI + рецепты   │
                    │  кастомный integration:  │
                    │  стейт-машины режимов    │
                    └──────────────────────────┘
```

**Разделение ответственности — критично для безопасности:**

- **ESP32 (ESPHome)** — единственный, кто физически управляет реле. Знает только примитивы: «выставь мощность ТЭНа N%», «открой клапан», «помпа M%». Имеет независимые safety-инварианты, которые отрубают железо при их нарушении даже без команды сверху.
- **Home Assistant** — высокоуровневая логика режимов, рецепты, UI. Падение HA не должно приводить к небезопасному состоянию: ESP должен сам уйти в safe state по watchdog.

### Аппаратная безопасность (КРИТИЧНО — не экономить)

| Компонент | Модель | Кол-во | Назначение |
|---|---|---|---|
| Термопредохранитель | биметалл 130–140°C, NC | 1 | **Последовательно с катушкой контактора ТЭНа**. Срабатывает физически независимо от ESP. |
| Силовой контактор | модульный AC 230В, 25А, NO | 1 | Включается реле «enable» с ESP, разрывается термопредохранителем. Без него ТЭН не запитан в принципе. |
| Дублирующий датчик аварии | биметаллический switch 110°C | 1 | На кубе, в линию enable-контактора. |
| Звуковой сигнал | пьезопищалка 5В, активный | 1 | Аварии / завершение режима. |
| Кнопка аварийной остановки | грибок, NC, фиксируемая | 1 | В линию enable-контактора. Физически разрывает силу. |

**Принцип hardware safety:** ТЭН питается через цепочку `автомат → УЗО → E-stop (NC) → биметалл куба (NC) → термопредохранитель (NC) → катушка контактора → SSR → ТЭН`. Любой разрыв в цепи NC = ТЭН обесточен, и софт тут не участвует.

## 5. Программный стек

### 5.1 ESPHome-прошивка (`firmware/esp32-still.yaml`)

Делает только то, что обязано:

- читает все датчики (DS18B20 + BME280) с периодом 1 с;
- публикует sensor entities в HA через native API;
- принимает команды: `set_heater_power` (0-100%), `valve` (on/off), `pump_power` (0-100%), `enable_contactor` (on/off);
- ШИМ ТЭНа через `ac_dimmer` компонент (он умеет cycle-skipping для медленных нагрузок);
- **safety automations** (выполняются на самом ESP, без HA):
  - watchdog: если нет валидной команды от HA > 30 с → heater=0, valve=closed, contactor=off, beep;
  - T куба > `max_kub_temp` (по умолчанию 105°C) → heater=0;
  - T любого критичного датчика == NaN или вне диапазона `(-10, 130)` дольше 5 с → heater=0;
  - E-stop input == low → heater=0, valve=closed, contactor=off;
  - при загрузке: всё в safe state, контактор включается только по явной команде.

### 5.2 Home Assistant — кастомная интеграция `custom_components/craftspirits/`

Стейт-машина режимов на Python. Почему интеграция, а не YAML-automations: для старт-стопа нужны временные ряды, скользящие производные, гистерезисы — это в YAML превращается в нечитаемую кашу.

```
custom_components/craftspirits/
├── __init__.py           # setup, координатор
├── manifest.json
├── const.py
├── coordinator.py        # подписка на sensor states ESP
├── modes/
│   ├── base.py           # абстрактная Mode (enter/tick/exit, transitions)
│   ├── potstill.py       # дистилляция
│   ├── reflux_startstop.py
│   ├── reflux_pwm.py
│   └── dephlegmator_pid.py
├── safety.py             # барокоррекция, плавность setpoint
├── recipe.py             # загрузка/сохранение JSON рецептов
├── services.yaml         # craftspirits.start_mode / stop / change_phase
└── translations/{en,ru}.json
```

### 5.3 Lovelace UI

Дашборд с:
- большой график T(куба) / T(царги) / мощность / клапан;
- текущая фаза + время в фазе;
- крупные кнопки: «Стоп», «Перейти к телу», «Перейти к хвостам», «Готово»;
- настройки порогов (свернуто).

### 5.4 Симулятор для разработки (`sim/`)

Простая модель куба+царги (тепловой баланс + уравнение Антуана для бинарной смеси этанол-вода) на Python. Позволяет крутить стейт-машины без железа. Запускается как FastAPI, эмулирует ESPHome native API.

## 6. Алгоритмы режимов

### 6.1 Дистилляция (потстил)

```
INIT → HEAT_UP → DISTILLING → SHUTDOWN
```

- `HEAT_UP`: heater=100%, ждём T_kub ≥ `t_start` (по умолч. 80°C).
- `DISTILLING`: heater=`p_work` (60-80%), клапан всегда открыт. Логируем.
- Переход в `SHUTDOWN`: T_kub ≥ `t_stop` (98-99°C, с барокоррекцией) ИЛИ dT_kub/dt > порога (вода пошла).
- `SHUTDOWN`: heater=0, beep, журнал.

### 6.2 Ректификация старт-стоп

```
INIT → HEAT_UP → STABILIZE_TR → HEADS → BODY → TAILS → SHUTDOWN
                                  ↑___pulse___↓
```

- `HEAT_UP`: heater=100%, до T_low_tsarga > 60°C (пар дошёл).
- `STABILIZE_TR`: heater=`p_work_heads`, клапан закрыт, ждём `t_stable` минут с условием |dT_top/dt| < ε (захлёб закончен, флегма пошла).
- `HEADS`: повторяющийся цикл `open(t_open_heads) → close(t_pause_heads)`, длится либо по объёму (если есть счётчик), либо по T_kub ≥ `t_kub_body`.
- `BODY`: цикл `open(t_open_body) → close(wait_until |dT_top/dt|<ε)`. Главное условие выхода: T_top > `t_top_max` (~78.5°C+коррекция) дольше `t_dwell` секунд.
- `TAILS`: открыть полностью либо в другую ёмкость (опц. второй клапан), до T_kub ≥ `t_kub_stop`.
- `SHUTDOWN`: heater=0, valve=closed.

Все пороги — числа в HA (input_number entities), редактируются из UI, сохраняются в рецепте.

### 6.3 ШИМ-отбор

Альтернатива старт-стопу: клапан открывается на `duty * period`, `duty` пересчитывается каждые N секунд по PID от ΔT(top - top_setpoint). Лучше, когда клапан/насос позволяет плавную регулировку.

### 6.4 PID дефлегматора

Если охлаждение дефлегматора управляется (клапан воды или PWM-помпа): PID по T_top → расход. Цель — держать T_top чуть выше setpoint, не давая колонне «закиснуть».

## 10. Открытые вопросы (решаем по ходу)

1. **Помпа охлаждения** — 220В с релейным управлением или 12/24В с ШИМ? Влияет на BOM.
2. **Учёт объёма отбора** — ставим расходомер (например YF-S401) или считаем «на глаз» по времени открытия клапана?
3. **Второй клапан под хвосты** — нужен или сольём в ту же ёмкость и отделим вручную?
4. **Корпус** — DIN-щит на стене или переносной кейс?
5. **Резервирование** — ставим UPS на ESP+роутер? (Без него потеря Wi-Fi на минуту = принудительный safe shutdown по watchdog.)
