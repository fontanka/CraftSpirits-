# CraftSpirits Simulator

Симулятор куба+колонны+узла отбора (LM) для dry-run проверки логики стейт-машины
перед сборкой реального железа.

## Что моделирует

- **Физика**: тепловой баланс куба, кипение бинарной смеси этанол-вода (Antoine),
  обогащение пара в колонне с инерцией ~90 сек, конденсация на обратном
  холодильнике, тепловой баланс охлаждающей воды
- **Хардвер**: GPIO-выходы ESP (heater PWM, valve_takeoff, valve_water, contactor),
  «чтение датчиков» (с поддержкой fault-injection NaN)
- **Контроллер**: стейт-машина для LM-ректификации (INIT → HEAT_UP → STABILIZE →
  HEADS → STABILIZE2 → BODY → TAILS → SHUTDOWN), потстил, ШИМ узла отбора,
  барокоррекция, tripwires по T_water_out, watchdog, emergency-handling
- **Fault injection** для проверки safety:
  - обрыв любого датчика → NaN
  - залипание клапана узла отбора OPEN/CLOSED
  - пробой SSR ТЭНа (нагрев 100 % независимо от команды)
  - закрытый кран воды (нет потока несмотря на открытый соленоид)
  - E-stop / биметалл / термопред
  - отключение Pi → ESP-watchdog должен сработать через 30 сек

## Установка

```bash
cd sim/
pip install -r requirements.txt
```

## Запуск

```bash
python server.py
```

Открыть в браузере: <http://localhost:8000>

## Что в UI

- **Большие индикаторы** температур (T_kub, T_head, T_water_in, T_water_out)
  с цветовой кодировкой и подсветкой `SENSOR FAIL` при NaN
- **Фаза процесса** — большой цветной тег (HEAT_UP/HEADS/BODY/TAILS/...)
- **Выходы железа** — мощность ТЭНа (полоса), LED-индикаторы клапанов и контактора,
  текущий duty cycle ШИМ узла отбора
- **График** последних 30 мин sim-времени: T_kub (красная), T_head (оранжевая),
  T_water_out (синяя)
- **Статистика**: объём куба, крепость браги, V продукта, его крепость, состав
  пара наверху, мощность на пар, давление атм.
- **Управление**:
  - Старт сессии с параметрами рецепта (V, крепость, мощность, duty cycles, время стабилизации)
  - Стоп / Пауза / Reset
  - Скорость симуляции ×0.1 ... ×600 (×60 = час за минуту, удобно для длинных фаз)
- **Fault injection panel** — клик включает/выключает соответствующую неисправность
- **Лог** переходов и алертов

## Типовой сценарий проверки

1. Поставить скорость ×60
2. Стартовать сессию REFLUX с дефолтами (18 L браги 12 %, p_work 60 %)
3. Наблюдать:
   - HEAT_UP: куб греется, T_kub растёт до точки кипения смеси (~82 °C)
   - При T_head > 78 °C переход в STABILIZE
   - STABILIZE 10 мин — клапан закрыт, total reflux
   - HEADS — ШИМ клапана с низким duty 15 %, объём продукта растёт медленно
   - При T_kub > 88 °C → STABILIZE2 → BODY
   - BODY — основной отбор, duty 40 %
   - При T_head поднимется выше 78.5 °C (хвосты пробились) → TAILS
   - TAILS до T_kub > 99 °C → SHUTDOWN → DONE
4. Проверить safety: на любом этапе включить «E-stop» → должен быть мгновенный EMERGENCY
5. Включить «Pi disconnected» → через 30 сек sim-time должен сработать watchdog

## Файлы

- `still.py` — физическая модель (без зависимостей от FastAPI)
- `controller.py` — стейт-машина и алгоритм
- `server.py` — FastAPI + WebSocket
- `static/index.html` — веб-UI

## Что НЕ моделируется (намеренно)

- Точная VLE с реальным азеотропом (используется упрощённый Antoine)
- Гидродинамика колонны (захлёб через косвенный признак — рост ΔT воды, не давление)
- Тепловые потери через изоляцию (грубо 25 Вт/К)
- Реальная инерция датчиков DS18B20 (предполагается мгновенной)
- Сеть Wi-Fi (Pi и ESP считаются одним процессом, кроме watchdog-теста)
